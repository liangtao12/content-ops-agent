## CO-FUNC-001 非法格式或过去时间仍可创建排期

| 字段 | 内容 |
|---|---|
| 严重程度 | 高 |
| 优先级 | P1 |
| 状态 | 已复现 |
| 发现方式 | 补充执行（既有 pytest 未覆盖该分支） |
| 关联用例 | CO-15 |

- **现象与证据**：`write_schedule` 未校验 `publish_at` 的格式与时间范围，直接落盘。
- **复现步骤**：分别以 `publish_at=not-a-date`、`publish_at=2020-01-01T00:00` 调用排期。
- **预期结果**：非法格式和过去时间均被拒绝。
- **实际结果**：两次调用均返回 `scheduled`，并生成 S0001、S0002 两条日程。
- **影响**：可直接产出无效日程；下游若按 `publish_at` 排序或推送，会出现"发布到过去"的脏数据，且无法通过审批链路拦截（因为排期发生在审批之后）。
- **建议**：增加 ISO 8601 解析（失败即 422）、统一时区、拒绝早于当前时间的 `publish_at`；补一条 pytest 覆盖两个分支。
- **复核结果**：待修复。

## CO-DEP-001 重启后的 checkpoint 保存异常

| 字段 | 内容 |
|---|---|
| 严重程度 | 高 |
| 优先级 | P0 |
| 状态 | 已复现 |
| 发现方式 | 自动化回归（`test_checkpoint_survives_new_graph_instance`） |
| 关联用例 | CO-14 |

- **现象与证据**：`JsonPlusSerializer` 对象缺少 `dumps` 方法。
- **复现步骤**：执行 `backend/tests/test_reliability.py::test_checkpoint_survives_new_graph_instance`。
- **预期结果**：中断状态写入 SQLite，换新图实例后可继续审批。
- **实际结果**：`AttributeError: JsonPlusSerializer object has no attribute dumps`。
- **影响**：Human-in-the-loop 的"跨重启续跑"在本次依赖组合下失效——这是项目最核心的能力之一，属于"功能存在但不可用"，优先级高于其他两条。
- **建议**：锁定 LangGraph / checkpoint 依赖的兼容版本（或在 `persistence.py` 里显式传入 serde 实现），并补一条跨进程重启的集成测试防止再次回归。
- **复核结果**：待修复。

|---|---|
